## 1. 市场问题定义

### 1.1 用户痛点（按角色）

| 用户角色 | 痛点 | 证据（从架构反推） |
|---------|------|------------------|
| **开发者** | 1. 传统客服 Widget 太重，影响页面性能<br>2. API 文档不完整，集成调试耗时<br>3. 无法自托管，数据在第三方 | WebSocket 连接池优化设计、完整 OpenAPI 规范、自托管支持代码 |
| **产品经理** | 1. 客服数据无法与产品分析打通<br>2. AI 回复效果不可控，品牌形象受损<br>3. 缺少自定义能力，只能用别人的 UI | Knowledge Clarification 知识澄清流、自定义事件支持、Headless 架构 |
| **客服主管** | 1. 重复问题太多，团队效率低<br>2. 无法量化 AI 实际效果<br>3. 客服工具切换太频繁 | AI Pipeline 自动回复、30 天滚动用量计量、统一 WebSocket 实时工作台 |
| **访客** | 1. 排队等待客服太久<br>2. 问题描述一遍又一遍<br>3. 客服回复太慢 | Visitor Memory 访客记忆、AI 7x24 自动回复、实时状态推送 |

## 3. 用例定义

### 3.1 核心用例矩阵

| 用例 ID | 用例名称 | 角色 | 描述 |
|--------|---------|------|------|
| UC-001 | 访客发起聊天 | 网站访客 | 在网站右下角点击 Widget 按钮，打开聊天窗口，发送消息 |
| UC-002 | AI 自动回复 | 系统 | 访客消息发送后，AI Pipeline 检索知识库，生成并推送回复 |
| UC-003 | AI 无法解决转人工 | 系统 + 客服 | AI 判断无法处理，自动分配给在线客服，推送上下文 |
| UC-004 | 客服回复访客 | 客服人员 | 客服在工作台看到对话，打字回复，访客实时收到 |
| UC-005 | 训练知识库 | 管理员 | 输入网址、上传文档，系统自动爬取、向量化、存入知识库 |
| UC-006 | 查看数据分析 | 管理员/客服主管 | 在仪表板查看对话量、AI 解决率、响应时间等指标 |
| UC-007 | 管理团队成员 | 组织所有者 | 邀请、移除团队成员，分配角色权限 |
| UC-008 | 自托管部署 | 开发者 | 按照文档，部署到自己的服务器 / Kubernetes / Vercel |
| UC-009 | Webhook 集成 | 开发者 | 配置对话创建/结束等事件的 Webhook 回调，同步到内部系统 |
| UC-010 | API 调用 | 开发者 | 通过 REST API 创建对话、发送消息、拉取历史数据 |

### 3.2 关键用户旅程

#### 旅程 1：开发者 5 分钟集成

```
第 1 步：注册账号（1 分钟）
       ↓
第 2 步：创建网站，获取 embed 代码（30 秒）
       ↓
第 3 步：粘贴到自己网站的 <head> 中（30 秒）
       ↓
第 4 步：测试访客聊天，确认 Widget 正常加载（1 分钟）
       ↓
第 5 步：输入 3 个知识库 URL 开始训练（2 分钟）
       ↓
完成 ✅ 总计：< 5 分钟
```

#### 旅程 2：AI 自动处理访客问题

```
访客打开聊天
       ↓
访客输入："你们支持哪些支付方式？"
       ↓
AI 检索知识库（< 500ms）
       ↓
匹配到 3 条相关知识片段
       ↓
AI 合成回复（< 2 秒）
       ↓
访客收到："我们支持信用卡（Visa、Mastercard）、PayPal、银行转账。请问还有其他问题吗？"
       ↓
访客问题解决，对话结束
```

## 4. 功能需求概述

### 4.1 功能模块（从架构反推）

| 模块 | 对应架构文档 | 核心功能 |
|------|------------|---------|
| **访客 Widget** | 01-SYSTEM-OVERVIEW | 聊天窗口、离线留言、文件上传、输入状态同步 |
| **实时消息系统** | 03-REAL-TIME-MESSAGING | WebSocket 连接、跨实例 Pub/Sub、连接注册表、在线状态 |
| **AI 对话管道** | 04-AI-CONVERSATION | 主管道实时回复、后台管道异步处理、智能决策引擎、工具调用 |
| **知识库 RAG** | 05-KNOWLEDGE-BASE | URL 爬取、文档上传、向量化、向量检索、知识澄清流、片段管理 |
| **访客追踪** | 06-VISITOR-TRACKING | 访客识别、浏览路径追踪、归因分析、访客记忆 |
| **计费系统** | 07-BILLING | 三级订阅、AI Credit 计量、用量限制、Polar 集成、故障降级 |
| **团队协作** | 09-DATA-MODEL | 多角色权限、对话分配、内部备注、转接 |
| **数据分析** | 01-SYSTEM-OVERVIEW | 对话量统计、AI 解决率、响应时间、用量报表 |
| **开放接口** | 01-SYSTEM-OVERVIEW | REST API v1、Webhook、OpenAPI 文档 |

### 4.2 最低可行产品 (MVP) 范围

**必须包含**：
- 访客聊天 Widget
- 客服工作台
- AI 自动回复（基于知识库）
- 知识库 URL 训练
- 三级计费 + 用量限制
- 基础数据分析

**可后续迭代**：
- 高级分析报表
- Slack/其他渠道集成
- 多语言
- iOS/Android SDK

## 5. 验收指标

### 5.1 产品市场匹配指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| **注册 → 集成转化率** | > 30% | 注册后 7 天内有访客消息 |
| **Free → Hobby 转化率** | > 5% | 注册后 30 天内升级 |
| **Hobby → Pro 转化率** | > 20% | 使用 90 天后升级 |
| **月留存率** | > 80% | 上月活跃客户本月仍活跃 |
| **AI 解决率** | > 60% | 对话结束不需要人工介入的比例 |
| **集成时间** | < 10 分钟（P50） | 从注册到第一条消息的时间 |

| 指标 | 目标值 |
|------|--------|
| Widget 加载时间 | < 500ms |
| AI 首条回复延迟 | < 2s（P95） |
| 消息送达延迟 | < 300ms（P95） |
| API 可用性 | > 99.9% |
| 知识库检索延迟 | < 500ms |

## 6. 风险与假设

### 6.1 已验证假设（代码存在 = 已验证）

✅ **技术可行性**：
- 实时 WebSocket 多实例架构可行（Redis Streams）
- AI RAG 检索与生成可以在 2 秒内完成
- 按网站的多租户计费隔离可行
- 自托管模式技术上可实现

### 6.2 未验证假设（需要市场验证）

❓ **市场需求**：
- 开发者是否真的愿意为 AI 客服付费？
- 自托管免费策略能否带来足够的口碑传播？
- "按网站计费"模式 vs "按座席计费"哪个更优？

❓ **产品体验**：
- AI 实际解决率能否达到 60%？
- 知识训练流程是否足够简单？
- 客服工作台效率能否超越竞品？
