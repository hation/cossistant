# 非功能需求文档

**所属模块**: 全局
**优先级**: P0
**版本**: v1.0

---

## 1. 性能需求

### 1.1 页面加载性能

| 指标 | 目标值 | 测量方式 | 优先级 |
|------|--------|---------|--------|
| **LCP (最大内容绘制)** | < 2.5s | Lighthouse / Chrome DevTools | P0 |
| **FID (首次输入延迟)** | < 100ms | Web Vitals | P0 |
| **CLS (累积布局偏移)** | < 0.1 | Web Vitals | P1 |
| **TTI (可交互时间)** | < 3.8s | Lighthouse | P1 |

### 1.2 API 响应性能

| 接口 | P95 目标 | 并发能力 | 优先级 |
|------|---------|---------|--------|
| **Widget 加载接口** | < 500ms | 10,000 QPS | P0 |
| **消息发送接口** | < 200ms | 5,000 QPS | P0 |
| **AI 回复接口** | < 2s | 1,000 并发 | P0 |
| **知识库检索** | < 500ms | 2,000 QPS | P1 |
| **数据分析报表** | < 3s | 100 并发 | P2 |

### 1.3 实时消息延迟

- 访客 → 客服的消息传递：< 500ms (P95)
- 打字状态同步：< 300ms (P95)
- 客服状态变更广播：< 1s

## 2. 安全性需求

### 2.1 认证与授权

| 需求 | 说明 | 优先级 |
|------|------|--------|
| **会话管理** | JWT HttpOnly Cookie，过期时间 24 小时 | P0 |
| **CSRF 防护** | 所有变更操作携带 CSRF Token | P0 |
| **权限校验** | 所有 API 必须校验用户角色，不能仅依赖前端隐藏 | P0 |
| **多因素认证** | Owner 账号支持 2FA（邮件 / TOTP） | P2 |

### 2.2 数据加密

- **传输层**：全站 HTTPS (TLS 1.3)，HSTS 启用
- **存储层**：
  - 密码：bcrypt 哈希 (cost factor = 12)
  - API Key：AES-256-GCM 加密存储
  - 个人数据：字段级加密（合规要求）
- **备份数据**：加密后存储

### 2.3 数据隔离

**多租户隔离原则**：
- 数据库层面：所有表必须有 `organization_id` 或 `website_id` 字段
- 查询层面：所有业务查询必须自动带上租户过滤（中间件保障，不能遗漏）
- 存储层面：向量数据库按组织分片隔离
- 审计：定期 SQL 审查，确保没有遗漏租户过滤的查询

### 2.4 隐私合规

- **GDPR 合规**：数据导出、数据删除权
- **Cookie 同意**：EU 用户首次访问显示 Cookie Banner
- **数据留存策略**：默认保留 2 年，可配置；过期自动归档/删除
- **DPA**：数据处理协议模板

## 3. 可靠性与可用性

### 3.1 SLA 目标

| 层级 | 可用性目标 | 年停机时间 | 说明 |
|------|-----------|-----------|------|
| **Core** (核心对话) | 99.99% | < 53 分钟 | 消息发送、接收、存储 |
| **Important** (重要功能) | 99.9% | < 8.8 小时 | 工作台、AI 回复、报表 |
| **Best Effort** (其他) | 99.5% | < 43 小时 | 设置、次要功能 |

### 3.2 容灾与降级

**分级降级策略**：

| 降级等级 | 触发条件 | 降级行为 |
|---------|---------|---------|
| **Level 1** | AI 服务响应慢或失败 | AI 建议功能关闭，但人工对话正常 |
| **Level 2** | 数据库主库压力大 | 报表查询延迟执行，只读查询切到从库 |
| **Level 3** | 消息队列阻塞 | 非关键事件（分析、通知）延迟处理 |
| **Level 4** | 严重流量洪峰 | 新注册暂停，现有客户服务保持 |

### 3.3 数据备份策略

- **数据库**：每日全量备份 + 实时 Binlog 归档，RPO < 5 分钟
- **对象存储**：版本化 + 跨区域复制
- **备份验证**：每周进行一次恢复演练，确保备份可用

## 4. 可扩展性

### 4.1 水平扩展

- **无状态服务**：所有 API 服务必须无状态，支持多实例部署
- **会话存储**：Redis，不能存在本地内存
- **数据库**：读写分离，按业务分库预留设计

### 4.2 限流设计

| 层级 | 限流策略 | 阈值 |
|------|---------|------|
| **IP 级** | 滑动窗口 | 1000 次/分钟 |
| **用户级** | 令牌桶 | 100 次/分钟 |
| **组织级** | 按套餐配额 | 各套餐不同 |
| **API 级** | 漏桶 | 按接口重要性配置 |

## 5. 可观测性

### 5.1 日志规范

**结构化日志字段标准**：
```
- timestamp: ISO 8601
- level: debug/info/warn/error
- service: api/workers/web
- trace_id: 分布式追踪 ID
- organization_id: 组织 ID（如适用）
- website_id: 网站 ID（如适用）
- user_id: 用户 ID（如适用）
- visitor_id: 访客 ID（如适用）
- duration_ms: 处理耗时（如适用）
- error.stack: 错误堆栈（如有）
```

### 5.2 核心告警

| 告警项 | 阈值 | 通知级别 |
|--------|------|---------|
| API 错误率 | > 1% 持续 5 分钟 | P0 (电话 + Slack) |
| 消息延迟 | P95 > 2s 持续 5 分钟 | P0 |
| 数据库 CPU | > 80% 持续 10 分钟 | P1 |
| Redis 内存 | > 80% | P1 |
| AI 服务失败率 | > 10% | P1 |
