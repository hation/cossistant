## 2. 知识库结构

### 2.1 内容模型

**单条知识（Knowledge Item）**：

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| **标题** | 字符串 | 该知识的简短描述 | ✅ |
| **问题问法** | 字符串数组 | 访客可能的提问方式（至少 2 种，越多越准） | ✅ |
| **回答内容** | Markdown | AI 发送给访客的标准回答 | ✅ |
| **分类** | 分类标签 | 如"产品功能"、"计费相关" | ❌ |
| **状态** | 枚举 | 草稿 / 已发布 / 已归档 | ✅ |
| **语言** | 枚举 | 中文 / 英文 / 日文等 | ✅ |
| **内部备注** | 文本 | 仅团队可见的说明 | ❌ |

### 2.2 分类体系

**两级分类**：
- **一级分类**（Category）：产品功能 / 计费相关 / 账户安全 / 技术支持 / 其他
- **二级标签**（Tag）：可自定义，灵活打标（如"退款"、"API 调用"、"密码重置"）

## 3. 内容编辑与管理

### 3.1 编辑器功能

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **Markdown 支持** | 粗体、斜体、列表、链接、代码块 | P0 |
| **变量插入** | 支持 `{{公司名称}}`、`{{客服名称}}` 等变量，回复时自动替换 | P1 |
| **预览** | 编辑时可实时预览 AI 发送给访客的效果 | P0 |
| **版本历史** | 保存最近 10 次修改，支持回滚 | P2 |
| **相似性检测** | 添加新内容时，检测是否已有相似内容，避免重复 | P1 |

### 3.2 批量操作

- 批量导入（支持 CSV / Markdown 文件夹）
- 批量导出（备份目的）
- 批量修改分类/状态
- 批量删除（需二次确认）

## 4. 向量检索配置

### 4.1 Embedding 模型

| 模型 | 维度 | 适用场景 |
|------|------|---------|
| **text-embedding-3-small** | 1536d | 主力，平衡性能与成本 |
| **text-embedding-3-large** | 3072d | 高精度场景，小知识库可选 |

### 4.2 检索策略

**召回 → 重排序 两阶段**：

```
阶段一：召回（快速）
  使用向量相似度，召回 Top 20 候选
  相似度阈值：> 0.7
  
  阶段二：重排序（精确）
    使用交叉编码器重排序
    结合关键词匹配加分
    输出最终 Top 3 最相关结果
```

**相似度分数含义**：
- > 0.9：非常相关 → 直接使用
- 0.7-0.9：相关 → AI 可组合使用
- < 0.7：不相关 → 不使用，考虑澄清或转接

## 5. 数据看板

### 5.1 知识库使用指标

| 指标 | 说明 | 计算方式 |
|------|------|---------|
| **总命中次数** | 知识被 AI 引用的次数 | 每条消息引用的知识计数 |
| **Top 命中** | 被引用最多的 Top 10 知识 | 按次数排序 |
| **零命中知识** | 从未被使用的知识（可能是质量问题） | 命中次数 = 0 |
| **解决率** | 引用该知识后，访客是否继续追问 | 引用后 3 分钟内无新消息 = 解决 |
| **覆盖率** | 多少访客问题匹配到了知识库 | 匹配数 / 总问题数 |

### 5.2 优化建议

**自动识别待优化内容**：
- 📉 低命中但高浏览的知识 → 可能标题/问法不够好
- 📉 高命中但低解决率的知识 → 可能内容质量有问题
- 📈 频繁出现但无对应知识的问题 → 建议添加新知识
